[커밋 메시지 규칙]
1. 커밋 제목은 50자 이내로, 영문 소문자와 아래 Prefix 중 하나를 사용하여 작성할 것:
   - feat: 새로운 기능 추가 (예: 호텔 추천 알고리즘 개선, 검색 필터 추가)
   - fix: 버그 수정 (예: 결제 오류 해결, 잘못된 추천 데이터 수정)
   - docs: 문서 수정 (README, API 명세서 등)
   - style: 코드 포맷팅, 세미콜론 누락 수정 (비즈니스 로직 변경 없음)
   - refactor: 코드 리팩토링 (기능 변화 없이 코드 구조 개선)
   - test: 테스트 코드 추가 또는 수정
   - chore: 빌드 업무 수정, 패키지 매니저 설정 등

2. 커밋 제목 예시:
   - feat: 사용자 맞춤형 호텔 추천 로직 추가
   - fix: 리뷰 데이터 로딩 시 발생하는 널포인터 예외 해결

3. 커밋 본문은 한글로 작성하며, '존댓말(~습니다, ~합니다)'을 사용할 것.
4. 변경된 핵심 파일명과 변경 이유를 명확하게 포함할 것. (예: `recommendation.py`의 호텔 필터링 속도 개선을 위해 리스트 내포 사용)
5. 관련된 지라(Jira) 티켓 번호나 깃허브 이슈 번호가 있다면 마지막 줄에 기입할 것 (예: Resolves: #123)

[Pull Request (PR) 규칙]
1. PR 제목은 핵심 변경 사항을 요약하며, 이모지를 하나 이상 포함할 것 (예: 🚀 추천 알고리즘 개선, 🐛 예약 오류 수정)
2. 본문은 다음 세 가지 섹션을 반드시 포함하고 마크다운 문법을 지킬 것:
   ## Why (변경 배경)
   - 변경을 하게 된 이유 (비즈니스적 필요성, 버그 원인 등)
   ## What (핵심 변경 사항)
   - 무엇이 변경되었는지 1~3개의 불릿 포인트로 기술
   ## How to Test (테스트 방법)
   - 리뷰어가 해당 변경 사항을 어떻게 테스트할 수 있는지 구체적인 방법 제시
3. 여행/호텔 도메인 용어를 정확히 사용할 것 (예: User -> Traveler, Room -> Accommodation 등 서비스 내 약속어 사용)
4. (선택) 서비스의 AI 모델과 관련된 변경사항인 경우, 모델 성능 평가 지표(정확도 등)의 변화를 'Why' 또는 'What' 섹션에 간략히 언급할 것.
